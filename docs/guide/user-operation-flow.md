# TracePulse ユーザー向け基本操作フロー

本書は、TracePulse を「ユーザーが実際に利用する」前提で、最も自然な操作の流れを整理したガイドです。

注意:
- ここで示す操作は、製品としての本来の利用形態です。
- 現時点の `src/app/mod.rs` にある `192.168.1.x` の固定IPは、動作確認用のサンプルであり、ユーザー向けの運用方法ではありません。
- 正しい利用では、設定ファイルやアプリ内の機器登録手順を使って、対象機器を登録してから監視を開始します。

## 1. はじめに

TracePulse は、ネットワーク機器の状態を SNMP v2c で取得し、通信不良の予兆を可視化するポータブル監視ツールです。

利用形態は次の 2 通りです。

- CLI/TUI モード: `--cli`
  - 現場の一時診断、1〜数台の手軽な確認に向く
- WebGUI モード: `--web`
  - 複数機器の監視・ダッシュボード表示に向く

## 表示名・タグと一括命名

- 機器詳細の「表示名・タグを編集」から和名を設定できます。未設定時は元の
  sysName、次にIPを表示します。タグは入力後にEnterまたは追加ボタンで確定し、
  チップの削除ボタンで取り除きます。
- ダッシュボードの検索は表示名・元ホスト名・IP・タグを対象とします。
- チェックボックスで対象を選び「一括リネーム（連番付与）」を開きます。
  接頭辞（例：大阪支店SW-）、開始番号、ゼロ埋め桁数、任意の接尾辞を入力し、
  IP昇順または選択順でプレビューしてから適用します。入力変更後は再プレビューが必要です。
  IP昇順は数値順（IPv4、IPv6の順）、選択順はチェックした順です。
- 検索中も選択は維持され、先頭のチェックボックスは表示中の機器のみを操作します。
  一括更新は全件成功または全件取消となり、途中まで保存されることはありません。
- TUIでも和名を優先しタグを表示します。選択した機器の元ホスト名とIPは一覧枠下部で確認できます。
  再探索やポーリングは表示名・タグを上書きしません。
- 旧DBは起動時に自動移行されます。表示名は最大512文字、タグは最大64個
  （各1～64文字）、制御文字不可です。一括命名は最大1,000台、
  ゼロ埋め0～10桁、開始番号0～4,294,967,295で、連番の桁あふれは拒否します。
  元のsysName・IP・監視設定は変更しません。

APIの詳細と入力例は[READMEのDevice aliasesセクション](../../README.md#device-aliases-tags-and-sequential-naming)を参照してください。

## 2. 初期設定

### 2.1 実行ファイルの配置

アプリを展開後、実行ファイルと同じディレクトリに以下を配置します。

- `trace-pulse.exe` または `trace-pulse`
- `config.toml`
- `data.db`

`config.toml` はユーザー設定の入口です。最低限、SNMP のコミュニティ名とポーリング間隔を定義します。

例:

```toml
[web]
port = 8080

[polling]
interval_seconds = 30

[snmp]
default_community = "public"

[alert]
spike_threshold = 10
health_warning_threshold = 80
health_critical_threshold = 60
cpu = { warning = 80.0, critical = 90.0 }
memory = { warning = 80.0, critical = 90.0 }
bandwidth = { warning = 80.0, critical = 90.0 }
error_rate = { warning = 5.0, critical = 10.0 }

[retention]
history_days = 7
```

### 2.2 実行開始

CLI/TUI モード:

```bash
trace-pulse --cli
```

WebGUI モード:

```bash
trace-pulse --web
```

WebGUI はブラウザで `http://localhost:8080` を開いて利用します。

ポートを変更する場合は、次のように起動します。

```bash
trace-pulse --web --port 9090
```

この場合のアクセス先は `http://127.0.0.1:9090` です。`--port=9090` 形式も使えます。常用するポートは実行ファイルと同じディレクトリの `config.toml` の `[web] port` に設定してください。優先順位は起動引数、設定ファイル、初期値8080の順です。有効範囲は1〜65535の整数で、起動引数の値は設定ファイルに保存しません。待受アドレスはローカルの `127.0.0.1` のままです。

### 2.3 WebGUIのセットアップガイド

ダッシュボードで登録済み機器が0台と確認でき、ブラウザにガイドの完了・スキップ記録がない場合、セットアップガイドが自動表示されます。既に機器を登録済みの場合や、機器一覧APIへの接続に失敗した場合は自動表示しません。

自動表示時だけ、英語表記の言語選択画面を最初に表示します。「Japanese」または「English」を選択して進むと、ガイドとWebGUI全体が選択した言語に切り替わります。ステップ1の「戻る」から言語選択へ戻り、選び直せます。選択は既存の言語設定（`localStorage`の`tracepulse-lang`）に保存され、再読込後も維持されます。手動でガイドを開く場合は言語選択を挟まず、現在の表示言語で開始します。

1. Welcome画面からセットアップを開始します。
2. IPv4 CIDR（例: `192.168.1.0/24`）とSNMP v2cコミュニティを入力して探索します。ガイドではCIDRを1つ、`/24`〜`/32`の範囲で指定できます。検出した機器から監視対象を選択し、登録すると監視が自動的に開始されます。登録済み機器は候補から除外されます。
3. 任意のアラート設定ステップから設定画面へ移動し、しきい値を変更できます。Community版はアラートのローカル記録・ダッシュボード表示に対応しますが、外部への通知送信は提供していません。

言語選択画面はEscキー、それ以降のステップは「スキップ」またはEscキーで通常画面に戻れます。言語選択前に閉じた場合は言語設定を変更せず、自動表示の抑止記録だけを保存します。探索中のスキップはブラウザの進捗取得を停止しますが、サーバー上で開始済みの探索は終了まで継続します。登録APIに送信済みの処理も取り消されません。

「完了」「スキップ」、またはガイドから設定画面への移動をブラウザの`localStorage`（`tracepulse-onboarding-v1`）に記録し、以降の自動表示を抑止します。コミュニティはこの記録には保存しません。別のブラウザや接続先では記録が共有されず、ストレージが利用できない場合は未登録状態で再表示されることがあります。

ダッシュボード上部の「セットアップガイド」ボタンは、完了・スキップ・Escで閉じるなどの記録がある場合は非表示になります。再実行する場合は、設定画面の「セットアップガイド」ボタンからいつでも開けます。探索・登録に失敗した場合は同じステップで再試行でき、登録せずに次へ進むこともできます。

## 3. 機器の登録フロー

ユーザーが実際に監視対象を追加する方法は、主に次の 3 つです。

### 3.1 自動検出（推奨）

対象のネットワーク範囲を CIDR で指定して、SNMP 応答がある機器を自動検出します。

例:

- `192.168.1.0/24`
- `10.0.0.0/24`

自動検出では、以下を行います。

1. 指定 CIDR を解析する
2. ホスト候補を列挙する
3. SNMP v2c で応答した機器を抽出する
4. ユーザーが候補から登録対象を選ぶ

この方法は、現場で対象機器の IP を一つずつ調べるよりも効率的です。

### 3.2 手動登録

SNMP 応答が分かっている機器については、IP と community を直接登録します。

入力項目の例:

- 機器名
- IP アドレス
- SNMP community
- 種別（router / switch / unknown）

### 3.3 CSV / TOML 読み込み

複数機器をまとめて追加したい場合は、CSV または TOML から読み込む想定です。

例:

```toml
[[devices]]
name = "core-sw-01"
ip = "192.168.1.10"
community = "public"
type = "switch"
```

または CSV:

```csv
name,ip,community,type
core-sw-01,192.168.1.10,public,switch
core-rtr-01,192.168.1.20,public,router
```

## 4. 監視開始の流れ

機器を登録したら、次の順で監視を開始します。

1. 通知対象の機器を登録
2. 監視間隔を設定
3. SNMP v2c で機器に接続
4. 収集ループを開始
5. インターフェース情報と CPU/メモリの取得を開始

監視対象に対して、以下が定期的に収集されます。

- インターフェースリンク状態
- In/Out エラー数
- Drop / Discard 数
- 帯域利用率
- CPU 使用率
- メモリ使用率

## 5. アラート確認フロー

TracePulse は、収集した値から「予兆」を判定します。

### 5.1 スパイク検知

直近ポーリングとの差分で、エラー数が急増した場合にアラート化します。

### 5.2 エラー率検知

設定画面ではCPU・メモリ・帯域利用率・エラー率ごとにWarning / Criticalを%で入力します（0 < Warning < Critical <= 100）。値が閾値以上になると、Criticalを優先して発報します。CPUが100%なら、他のメトリクスやヘルススコアに関係なくCPUのCriticalアラートになります。

エラー率は、ポーリング間の差分を使い「エラー数 / (正常パケット数 + エラー数) x 100」で算出します。1%の閾値は`1`と入力します。初回サンプル・無通信・カウンタリセット時はエラー率を判定しません。帯域・エラー率のアラートにはインターフェース名も記録します。

同じ重要度の超過が続く間は再発報せず、重要度が変わった場合と回復後の再超過時に発報します。機器ステータスは個別閾値の最大重要度を表示します。スパイク検知と機器応答なしの検知は引き続き独立して動作します。

### 5.3 健全度スコア

端末ごとに100点満点のスコアをダッシュボードに表示します。スコアは表示専用で、アラート発報条件には使いません。CPU・メモリ未取得時やOffline時は未取得表示になります。初期の色分けは次のとおりです（設定画面の表示専用欄で変更できます）。

- 80 点以上: Healthy
- 60 点以上 80 点未満: Warning
- 60 点未満: Critical

## 6. CLI/TUI での利用方法

CLI/TUI モードは、現場で 1〜数台を素早く見る用途に向いています。

基本的な流れ:

1. `trace-pulse --cli` を起動
2. 監視対象一覧を確認
3. 機器ごとの状態を確認
4. Warning / Critical の機器を絞り込む
5. エラー件数や帯域利用率を確認
6. 必要に応じて再確認または対処

## 7. WebGUI での利用方法

WebGUI モードは、複数台を継続監視したいときに向いています。

基本的な流れ:

1. `trace-pulse --web` を起動
2. ブラウザで `http://localhost:8080` を開く
3. 機器一覧と健全度を確認
4. エラー急増機器を確認
5. 直近のアラートを確認
6. 必要に応じて再監視・再調査を実施

## 8. 実運用でのおすすめ手順

現場で使うときは、次の順番が安定します。

1. まず 1 台で SNMP の応答確認を行う
2. CIDR で候補を探索する
3. 監視対象として登録する
4. 30 秒間隔で収集を開始する
5. 1〜2 サイクル観測して値が妥当か確認する
6. 必要に応じてしきい値を調整する
7. 実運用対象台数を増やす

## 9. 典型的な利用シナリオ

### シナリオ A: 現場での一時診断

- 1〜数台を確認したい
- すぐに診断したい
- 長時間の監視より短時間の確認が中心

→ CLI/TUI モードが適している

### シナリオ B: 複数拠点の継続監視

- 監視対象が複数台ある
- ダッシュボード表示が必要
- 常時確認したい

→ WebGUI モードが適している

## 10. フィールドでの注意点

- SNMP community が異なる場合は、個別機器ごとに設定する
- 監視先機器の 161/UDP が通ることを確認する
- 部分的に応答しない機器は offline 判定の対象になる
- しきい値は環境ごとに見直す

## 11. 本来の利用の結論

ユーザーが本当に使う形は、以下の流れが正しいです。

1. 実行ファイルを起動する
2. `config.toml` を準備する
3. 監視対象を自動検出または手動登録する
4. 監視を開始する
5. CLI か WebGUI で状態を確認する
6. アラートを見て対処する
7. 履歴と保持期間を活用して運用を継続する

これは、`src/app/mod.rs` で IP を直書きしてすぐ動かすような使い方ではなく、アプリがユーザーの操作で対象機器を登録して監視を開始する設計です。

本書で示した流れは、TracePulse の正式な利用イメージとして扱ってください。
